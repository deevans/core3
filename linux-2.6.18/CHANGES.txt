The following describes changes from the original Coredistro CD in ascending
order of the final build of a package. This file is influenced by Slackware.

pkgs/base/core_base-1+1.cpk: upgraded.
  Move to base/ subdirectory to facilitate upgraded installations.

  Removed the root user profile aliases -i. As I filed with Red Hat, this is
  harmful. It encourages the use of -f to avoid the forced interaction, and
  this misses the warnings that would come from -r used without it. The
  aliases are thus removed from /etc/profile. This should be consistent
  for the base package and for the IUR CD-ROM's /etc/profile (which base
  package installation is actually different from the installed
  systems).

  The package version is not incremented to +2 for packages that are rebuilt
  from the original Coredistro, but will remain at +1 regardless with the
  32-bit version to avoid confusion with the 64-bit build versioning and to
  continue emphasizing the rhetrospective nature of the 32-bit remaster builds.
  There have been a couple dozen full rebuilds of my Core from Coredistro over
  the years. In each case, the build date and kernel version have been noted
  so will remain distinct. The first 6.6 release (AMD64) in the summer of 2024
  has version core_base-2+1. The IUR ISO name contains the date and
  architecture build.

  Modified /etc/inittab to use /usr/bin/ path instead of /sbin/.
  Modified /etc/man.conf to compensate for change of directory of less.

  Removed the lost+found/ directory. This is a file system related
  directory that should be at the base of a writable file system, thus
  removing it from the IUR, but also removing it from the core_base
  package as inappropriate.

  Add a 15 second timeout. However, with the change to bzImage and a new
  kernel build for i486, maybe this needs to be changed again. The
  timeout may not be of value for an install, upgrade, or recovery.

  The /usr/sbin/ directory is gone. Be aware that the kernel expects /bin/pwd
  for building from source. The toolchain is also sensitive to this and to
  Bash's placement, and possibly ldconfig and sln in /sbin/ (which actually
  are static). /sbin/ is kept for now, but the future goal is /usr/bin/ for
  all system executables.

  /bin/sh has been moved to core_base from core_bash. This allows the
  administrator to point it to whatever shell they wish.

  The /usr/include/asm-generic symlink has been added for 2.6 kernel 
  support.

  Add the /sys file system.

pkgs/core_e2fsprogs-1.41.14+1.cpk: upgraded.
  This package uses /usr/bin/ for binaries, especially instead of /usr/sbin/.
  The /sbin/ directory is required on Linux by only a limited number of
  programs, in particular /sbin/init is hardcoded in the kernel (among other
  paths for finding init). /sbin/ was originally static binaries moved from
  /etc/ for booting needs only. At this point, it too is superfluous, and only
  a couple of packages build static binaries, but is kept for the critical
  programs (or perhaps better, symlinked). /usr/bin/ is favored over /bin/ with
  the expectation that /usr/ in general (e.g. not including /usr/local/)
  should remain on the root file system. This also means that the sbin/
  directory restriction to execution by only the root user is no longer
  practiced: reliance on user privilege is expected, and the execution
  of an administrative command is only effective when run as the root
  user for restricted operations.

  1.41 is the first version introducing ext4 support for later 2.6 
  kernels.

  Libraries are added for support of util-linux-ng.

pkgs/core_ncurses-5.9+1.cpk: rebuilt.
  Moved libraries to /usr/lib/.

  /usr/ was the original home directory, but an early research Unix DEC PDP
  disk fill required a second drive and things not related to booting were
  moved there under the idea of user land tools. Research Unix returned to
  using /bin/ and /lib/, leaving /usr/ to include files and home directories,
  but the idea of moving everything to /usr/ was in motion even in 2003. This
  begins looking at that change as the norm.

  With 5.7, the tack program is removed, developed separately. To build
  tack separately requires adding the tic library.

pkgs/core_binutils-2.16.1+1.cpk: upgraded.
  Manual pages and info manuals are uncompressed in Coredistro. Bzip2
  compression is now used for man pages and info manuals.

  In general, binaries on Coredistro are optimized for size. I've followed
  suit, as the drive size (and website upload storage) availability may be 
  limited. Build scripts will rely on the existing stripping capability of the
  Makefile (where recognized), or use --strip-unneeded as the common approach
  to binary stripping of debug and related symbols. -Os seems to be a happy
  mean between size and optimization, and will likely avoid unidentifiable
  gotchas that break functionality of the binary and save some time in
  troubleshooting.

  I'm open to individual package optimization suggestions for best practice.

pkgs/corepkg-7+1.cpk: upgraded.
  Josh has graciously licensed CorePKG to me under the GPL, now hosted by the
  GNU Project. He wanted the original available under all versions of the
  GPL. Revisions are under GPLv2+.

  CorePKG 7 has a Gzip compressed manual, a different path (/usr/bin/, instead
  of /sbin/), and uses the more command, instead of less, for POSIX 
  compatibility. The -R flag in 'less' is not POSIX compliant and util-linux
  'more' does this by default.

  For this install it is custom modified to use 'less -Rs' instead.
