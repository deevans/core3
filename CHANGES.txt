The following describes changes from Josh Devin's Core in ascending
order. This file is influenced by Slackware.

pkgs/base/core_base-1+1.cpk: added.
  Move to base/ subdirectory to facilitate upgrade based installations,
  and to avoid clobbering existing installs by accident.

  Removed the root user profile aliases -i. As I filed with Red Hat, this is
  harmful, and Red Hat agreed though I didn't pursue traction with Fedora.
  It encourages the use of -f to avoid the forced interaction, and this misses
  the warnings that would come from -r used without it. The aliases are thus
  removed from /etc/profile. This should be consistent for the base package
  and for the IUR CD-ROM's /etc/profile (which base package installation is
  actually different from the installed systems).

  The CorePKG metadata is distinct in its date and build values, which
  identifies the clear build change from the original Coredistro. The patch
  version in upgraded packages will remain at +1 regardless. The distribution
  is not maintained by updating packages. This is the responsibility of the 
  user. Thus, the user tracks their own patches by incrementing the patch
  number.

  Add /usr/bin/sh and /usr/man/man1/sh.1.bz2, removed from the Bash package.
  This allows another shell to be made the default by the user while still
  rebuilding or upgrading Bash. It was necessary to update /etc/passwd and
  the shebang lines of /etc/rc.d/ scripts.

  Removed the lost+found/ directory. This should be at the base of a
  writable file system. It is created when a file system is initialized,
  but also has its own command for creating it when needed. Removing it
  from the core_base package as inappropriate.

  The rr_moved/ directory is related to CD-ROM configuration, and should
  not be part of a base package.

  Modified /etc/man.conf to compensate for change of directory of less.

  Modified /etc/inittab to use /usr/bin/ path instead of /sbin/.

  The /usr/sbin/ directory is removed.

  In the future, /bin/ will be a symlink to /usr/bin/. Be aware that the
  kernel expects /bin/pwd for building from source. Some configure scripts
  hard link to /bin/sh so that is temporarily provided while building. The
  toolchain is also sensitive to this and to Bash's placement. Glibc builds
  of ldconfig and sln are static and left in /sbin/, but init is symlinked
  for compatibility.

  Supporting /dev/pts/, removed the ttyp# and ptyp# character devices, 
  and added ptmx.

  The fstab(5) and mount(8) manuals recommend proc be mounted as proc
  not none. This is entirely arbitrary, but the mount(8) manual argument
  that a device error of proc vs none is clearer make sense.

pkgs/core_binutils-2.16.1+1.cpk: upgraded.
  Manual pages and info manuals are uncompressed in Josh Devan's Core.
  Switch to Bzip2 compression.

  In general, build scripts rely on the existing strip capability of the
  Makefile (where recognized), or use --strip-unneeded as the common approach
  to binary stripping of debug and related symbols. Optimizing is for size,
  e.g. -Os: storage is a big deal for small systems. LFS suggested
  CC="gcc -s".

pkgs/core_corepkg-7+1.cpk: upgraded.
  Josh has graciously licensed CorePKG to me under the GPL, now hosted by the
  GNU Project.

  The -R flag in 'less' is not POSIX compliant and util-linux 'more' does
  this by default. For now, this is custom modified to use 'less -Rs' from
  upstream. 'more' is still a symlink to 'less' as with Devin's Core.
  The benefit is a browsable file (not one the goes down but not up).
/lost+found: removed.
  The lost+found/ directory should be at the base of a writable extended
  file system, not a read-only CD-ROM.
/rr_moved: removed.
  The rr_moved/ directory comes from using the -hide-rr-moved flag of
  the mkisofs (or xorrisofs) command. It is effectively unused with
  Core.
