pkgs/core_glibc-2.33+1.cpk: upgraded.
  NPTL replaces pthreads for Linux 2.4. This requires i486 builds, so
  through kernel 3.7, 80386 builds *require* no threading support. It
  is decided to abandon i386, especially where this is removed from
  upstream in 3.8.

  /sbin/ is repurposed for its original Sun-era intent to be for statically
  compiled programs (though that was for the boot process), and may be moved
  to /usr/ when moving glibc libraries there, completing the /usr/ merge, or
  removed entirely (with an /sbin/ symlink to /usr/bin/) for compatibilty.
  glibc is the only package that provides static binaries.

  Instead of a generic [info manual] reference, there is a singular info
  manual to install (even though there are several files) to the dir file,
  and thus is explictly noted.

  Libraries are still kept in /lib/. Though manual symlinking could
  make everything work in /usr/lib/, this is not straight forward.
  Postponing /usr/ merge until a newer version has better support.

  Version 2.7 had issues in one place with -Os, so '-g -O2' was
  used since that version.

pkgs/core_binutils-2.35.2+1.cpk: upgraded.
  Manual pages and info manuals are uncompressed in Josh Devan's Core.
  Switch to gzip compression, then bzip2. I'm not a fan of xz, due to
  known decompression integrity issues (though rarely seen from
  experience). However, the lz format for LZMA2 seems well done, and so
  may be considered for the future.

  In general, build scripts rely on the existing strip capability of the
  Makefile (where recognized), or use --strip-unneeded as the common approach
  to binary stripping of debug and related symbols. Optimizing is for size,
  e.g. -Os: storage is a big deal for small systems. LFS suggested
  CC="gcc -s".

pkgs/base/core_base-1+1.cpk: added.
  Move to base/ subdirectory to facilitate upgrade based installations,
  and to avoid clobbering existing installs by accident, though an
  upgrade script is no longer provided.

  Removed the root user profile aliases -i. As I filed with Red Hat, this is
  harmful, and Red Hat agreed, though I didn't pursue traction with
  Fedora. It encourages the use of -f to avoid the forced interaction,
  and this misses the warnings that would come from -r used without it. The
  aliases are thus removed from /etc/profile.

  The CorePKG package metadata is distinct in its date and build values,
  which identifies the clear build change from the original Coredistro. The
  patch version in upgraded packages will remain at +1 regardless. The
  distribution is not maintained by updating packages. This is the
  responsibility of the user. Thus, the user tracks their own patches by
  incrementing the patch number. This is also a reflection of the fact I
  did support this distribution for some time (see previous reference to
  upgrade script), where continuity of package versions was necessary.
  However, that does not fit the intended purpose of this distribution.

  Add /usr/bin/sh and /usr/man/man1/sh.1.bz2, removed from the Bash package.
  This allows another shell to be made the default by the user while still
  rebuilding or upgrading Bash. It was necessary to update /etc/passwd and
  the shebang lines of /etc/rc.d/ scripts, and a /bin/ symlink is added,
  pointing to /usr/bin/ for compatibility (make sure not to overwrite
  this symlink). The kernel expects /bin/pwd for building from source.
  Some configure scripts hard link to /bin/sh so that is temporarily
  provided while building. The toolchain is also sensitive to this and
  to Bash's placement.

  Removed the lost+found/ directory. This should be at the base of a
  writable file system. It is created when a file system is initialized,
  but also has its own command for creating it when needed.

  The rr_moved/ directory is related to CD-ROM configuration, and should
  not be part of a base package. It also reflects the use of the
  -hide-rr-moved flag of the mkisofs (or xorrisofs) command. It is
  effectively unused with Core, so that flag is not used in making the
  IUR.

  Modified /etc/man.conf to compensate for change of directory of
  the less command.

  Modified /etc/inittab to use /usr/bin/ path instead of /sbin/.
  The /usr/sbin/ directory is removed as superfluous and not consistent
  with its original Sun purpose for boot-dedicated static binaries.
  Glibc builds of ldconfig and sln are static and left in /sbin/, but
  init is symlinked for compatibility.

  Supporting /dev/pts/, removed the ttyp# and ptyp# character devices, 
  and added ptmx.

  The fstab(5) and mount(8) manuals recommend proc be mounted as proc
  not none. This is entirely arbitrary, but the mount(8) manual argument
  that a device error of proc vs none is clearer make sense.

  Removed the IUR /etc/modules.conf when upgrading to module-init-tools,
  (and kmod).
pkgs/core_base-1+1.cpk: removed.
pkgs/linux-4.20+1.cpk: added.
  With the need to install Linux headers separately, and with common
  confusion around needing to custom compile the kernel as part of the
  installation process, this was all put into a package, preserving the
  monolithic kernel build that is minimalistic, and keeping it out of
  the way of a custom kernel build.

  The /dev/pts/ mounted file system is used, replacing the BSD ptx
  devices of Devin's Core. The sys file system is added as part of
  Linux 2.6. Udev is not yet used, but is provided. /var/run/ is moved 
  to /run/ and on the IUR mounted as tmpfs. With newer versions of
  e2fsprogs, this is done for /tmp/ as well, avoiding the confusing
  message about Unix v0 when formatting /dev/ram0. tmpfs must be built
  into the kernel to support this.

  Though not stated, ppp 4.2.8 and beyond require kernel headers from
  linux 4.x, motivating the move from 3.10.108 (which is also EOL for
  support). Since the beginning of Core, I have followed the 2.4 kernel
  patch releases, maintained by Marcelo Tosatti, then by Willy Tarreau
  with 2.4.34 through 2.4.37.11. I followed Tarreau to the end of
  kernels 2.6.27, 2.6.32, and 3.10. Ending with 3.10.108, when moving
  to GCC 6, ppp 4.2.7 would no longer build. The 4.x kernel was needed.
  I tested against 4.4, 4.5, and 4.9, but decided to move to the final
  linux 4.20 release, and with it follow the mainline kernel instead of
  a patch release.
